# Daniel Ortiz Guide to Leet Code

If I were to restart from scratch for LC, I'd do the following, assuming a minimum understanding of a language (best: Python imo)

## 1. Start with [Blind 75](https://neetcode.io/practice)

As you go through each section, first review the core algorithm and build it from scratch if possible ("What I cannot create, I do not understand ~ Richard Feynman")

## 2. Go through [Neetcode 150](https://neetcode.io/practice)

These include questions from the blind 75, which is good, because spaced repetition is one of the best techniques to learn anything.

## 3. Do new problems

Especially in data structures / algorithms you still haven't grasped fully. Lists for those exist and most lists made by someone are fair game tbh

### Keep in Mind:

- [The 14 patterns](https://gist.github.com/tykurtz/3548a31f673588c05c89f9ca42067bc4) you encounter in most problems, they are extremely useful
- When there is a new problem, the following problem solving process brings immense clarity and structure:
  1. Clearly understanding the problem: What is the input, structure of the problem, what does a correct answer look like?
  2. What tools do I have available that could help me? What data structures could be used, what patterns can be applied? A complete "slow" solution is better than a vague "optimized" one with better complexity
  3. Psuedocode and/or drawing out the problem & psuedocode to ensure you're on the right track, saves a lot of time and brain space to catch errors or pivot early instead of later.
  4. Write out the code, using good naming conventions and cleanly (the interviewer is thinking, this could be what the code they write while on my team would look like, do I want this?)
  5. **ALWAYS** review your code at the end to catch errors and edge cases, before submitting. Much better than running and finding out.
- Keep going. Don't spend more than an hour on any problem, there are many more to learn, when you could just look at the solution, understand, and move on.
